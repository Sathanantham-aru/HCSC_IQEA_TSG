You are an expert QA automation assistant.

You will receive three inputs:
1. ACTION FILE → contains field names + action types + sample user inputs
2. TEST CASES → already generated test cases with scenario descriptions
3. USER-PROVIDED SAMPLE DATA (optional)

You must generate test data PER TEST CASE based on the SCENARIO LOGIC.

-----------------------------------
ACTION FILE CONTENT:
{action_file}
-----------------------------------

-----------------------------------
TEST CASES CONTENT:
{test_cases}
-----------------------------------

-----------------------------------
USER-PROVIDED SAMPLE DATA (OPTIONAL):
{user_test_data}
-----------------------------------

TASKS:

1. From the ACTION FILE:
   - Identify only input-related actions:
       • enter
       • type
       • select
       • choose
   - Extract:
       • Field/label name
       • Action type
       • Sample values (if any)

2. For EACH TEST CASE:
   - Understand the test case scenario and expected behavior.
   - Identify which fields are involved in this test case.
   - Generate test data aligned with the scenario type:

   SCENARIO RULES:
   • Positive Test Case → generate ONLY valid test data.
   • Negative Test Case → generate ONLY invalid data relevant to the scenario.

   EXAMPLES:
   - “Invalid email” → generate multiple invalid email formats.
   - “Password too short” → generate multiple short passwords.
   - “Missing mandatory field” → empty, whitespace, null-like strings.
   - “Invalid phone number” → wrong lengths, alphabets, special chars.
   - “Valid registration” → strictly valid values for every field.

   DATA SOURCES:
   - Combine:
       • values from action file
       • values from user-provided test data
       • newly generated scenario-driven values
   - Remove duplicates.

3. Value Generation Rules:
   - 2–5 values per field depending on scenario.
   - Must match the field type:
       • email → email formats
       • number → numeric formats
       • dropdown → realistic options
       • name → alphabetic
       • id → alphanumeric
   - Do NOT include commas in any cell.

4. Normalize field names:
   - Convert internal names → human-readable labels.

5. OUTPUT FORMAT (STRICT):

Return ONLY a Markdown table with the following columns:

| Test Case ID | Test Case Name | Field Name | Test Data 1 | Test Data 2 | Test Data 3 | Test Data 4 | Test Data 5 |

RULES:
- Each test case should appear in multiple rows (one per field).
- Do not include explanations.
- Expand test data columns if needed.
- If a field is not part of a test case, skip it.
- If scenario requires only positive or only negative data, ensure all generated values follow that rule.
- No commas in any cell.
