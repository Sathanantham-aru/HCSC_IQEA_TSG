## STEP 2 — UNIVERSAL AUTOMATION RULES

These rules apply regardless of which application is being automated.

### RULE 1: Desktop — Always Use Keyboard, Never Mouse
- Import send_keys ONLY as: from pywinauto.keyboard import send_keys
- NEVER use: .click(), .click_input(), .type_keys(), element.set_text()
- ALWAYS use: send_keys() for every single keystroke and key combination
- ALWAYS call dlg.set_focus() before every function that interacts with the desktop window
- ALWAYS call dlg.wait("visible", timeout=30) immediately after getting the window reference

### RULE 2: Desktop — Handle Start/Splash Screens
- ANY desktop application may show a start screen, splash screen, or welcome dialog on launch
- NEVER assume the main workspace is ready immediately after Application.start()
- ALWAYS add logic to dismiss start screens:
  - If a default option is highlighted (e.g., "New", "Blank", "Continue") → send_keys("{ENTER}")
  - If no selection exists → send_keys("^n") to open a new document/session
  - Always add time.sleep(5) after dismissing the start screen

### RULE 3: Desktop — Universal Keyboard Shortcut Mapping
When the workflow says "click X" or "select X" for a desktop app, convert it:

| Workflow Says | Use This |
|---|---|
| click Save / save file | send_keys("^s") |
| click Save As | send_keys("^s") — prefer this over Save As |
| click New / create new | send_keys("^n") or send_keys("{ENTER}") on start screen |
| click Open | send_keys("^o") |
| click Close / exit | send_keys("%{F4}") |
| click OK / Yes / Confirm | send_keys("{ENTER}") |
| click Cancel / No | send_keys("{ESC}") |
| click Next (wizard) | send_keys("{TAB}") then send_keys("{ENTER}") |
| click a menu item | send_keys("%") + accelerator key (e.g., send_keys("%f") for File) |
| tab between fields | send_keys("{TAB}") |
| move between rows/items | send_keys("{ENTER}") or send_keys("{DOWN}") |
| navigate to a cell/field | send_keys("^g") + target address + send_keys("{ENTER}") |
| select all text in field | send_keys("^a") |
| clear a field | send_keys("^a{BACKSPACE}") |
| press Enter/Return | send_keys("{ENTER}") |

### RULE 4: Web — Always Use ActionChains
- NEVER use element.send_keys() or element.click() for text input
- ALWAYS use ActionChains for typing and key presses:
  ```
  actions = ActionChains(driver)
  actions.send_keys("text").perform()
  actions.send_keys(Keys.ENTER).perform()
  ```
- For keyboard shortcuts in web apps:
  ```
  actions.key_down(Keys.ALT).send_keys("q").key_up(Keys.ALT).perform()
  actions.key_down(Keys.CONTROL).send_keys("s").key_up(Keys.CONTROL).perform()
  ```
- Exception: .click() IS allowed on elements found via find_element — only for clicking, not for typing

### RULE 5: Web — Login Sequence Pattern
For ANY web login flow, always follow this exact pattern:
```
driver.get(login_url)
time.sleep(5)
actions = ActionChains(driver)
actions.send_keys(username_or_email).perform()
time.sleep(2)
actions.send_keys(Keys.ENTER).perform()
time.sleep(5)
actions.send_keys(password).perform()
time.sleep(2)
actions.send_keys(Keys.ENTER).perform()
time.sleep(15)
try:
    actions.send_keys(Keys.ENTER).perform()   # dismiss any "stay signed in" dialog
except:
    pass
time.sleep(10)
```

### RULE 6: Web — Finding Elements
- ALWAYS prefer these XPath strategies in this priority order:
  1. By visible text: `//tag[contains(text(),'visible text')]`
  2. By button/link text: `//button[contains(text(),'label')]` or `//a[contains(text(),'label')]`
  3. By placeholder: `//input[@placeholder='hint text']`
  4. By name/id: `//input[@name='fieldname']` or `//input[@id='fieldid']`
  5. By role+label: `//*[@role='button' and contains(@aria-label,'label')]`
- NEVER use nth-child, positional XPath like `(//div)[3]`, or CSS class-based selectors
- NEVER use Tab-key navigation to find elements in web apps

### RULE 7: Window and Tab Switching
- After ANY action that may open a new browser tab or window, ALWAYS call switch_to_new_window(driver)
- Always add time.sleep(3) after switching
- Always implement switch_to_new_window() as a utility function:
  ```
  def switch_to_new_window(driver):
      current_window = driver.current_window_handle
      for handle in driver.window_handles:
          if handle != current_window:
              driver.switch_to.window(handle)
              break
  ```

### RULE 8: In-App Command Bar (Web Office Apps, Electron Apps)
When the workflow says "search for [command]" or "use command bar" or "find [action] option":
```
actions.key_down(Keys.ALT).send_keys("q").key_up(Keys.ALT).perform()
time.sleep(3)
actions.send_keys("command text here").perform()
time.sleep(2)
actions.send_keys(Keys.ENTER).perform()
time.sleep(10)
actions.send_keys(Keys.ENTER).perform()   # confirm any follow-up dialog
time.sleep(10)
```

### RULE 9: Save File (Desktop — Any App)
When the workflow says "save" or "save as [filename]":
```
send_keys("^s")
time.sleep(3)
send_keys("^a{BACKSPACE}")    # clear existing/default filename
time.sleep(1)
send_keys("your_filename")    # type new filename
time.sleep(1)
send_keys("{ENTER}")
time.sleep(10)                # wait for save/upload to complete
```

### RULE 10: Synchronization Timing Guide
Use these wait times based on operation type:

| Operation | Wait Time |
|---|---|
| After app launch | time.sleep(5) |
| After dismissing start screen | time.sleep(5) |
| After opening browser | time.sleep(3) |
| After navigating to URL | time.sleep(5) |
| After login / authentication | time.sleep(15) |
| After opening file in web app | time.sleep(5) |
| After window/tab switch | time.sleep(3) |
| After triggering save | time.sleep(3) |
| After cloud save completes | time.sleep(10) |
| After triggering download | time.sleep(10) |
| After any menu/dialog open | time.sleep(2) |
| After any form field entry | time.sleep(1) |
| After app close | time.sleep(5) |

## STEP 4 — CHROME BROWSER SETUP (ALWAYS USE THIS EXACT CONFIG)

```python
def open_browser():
    chrome_options = Options()
    chrome_options.add_argument("--disable-gpu")
    chrome_options.add_argument("--disable-software-rasterizer")
    chrome_options.add_argument("--remote-debugging-port=9222")
    chrome_options.add_argument("--no-sandbox")
    chrome_options.add_argument("--remote-allow-origins=*")
    chrome_options.add_argument("--disable-dev-shm-usage")
    driver = webdriver.Chrome(options=chrome_options)
    driver.maximize_window()
    return driver
```

## STEP 5 — HYBRID FLOW SEQUENCING

Execute steps in the order they appear in the workflow. Respect these transition rules:

- If workflow moves from desktop to web: finish all desktop steps, close the desktop app if not needed further, then open_browser()
- If workflow moves from web back to desktop: driver.quit() then re-attach or re-launch the desktop app
- If both run in parallel (e.g., copy data from web to desktop): keep both open, switch between them as needed
- Always wrap web automation in try/finally to ensure driver.quit() is called

## STEP 6 — RESILIENCE PATTERNS

Apply these patterns everywhere:

### Optional/Unpredictable Dialogs
Wrap steps that may or may not appear in try/except:
```python
try:
    # handle optional popup or dialog
    send_keys("{ENTER}")
except:
    pass
```

### Element Not Found Fallback
When finding web elements that might have variable locators:
```python
try:
    element = driver.find_element(By.XPATH, "//button[contains(text(),'Primary Label')]")
except:
    element = driver.find_element(By.XPATH, "//button[contains(text(),'Alternate Label')]")
element.click()
```
