================================================================================
THE CORE CONSTRAINT - PLEASE READ FIRST
================================================================================
Interactive action recording is IQEA's primary feature, and every user needs
their OWN browser.

Chrome therefore runs HEADED on a virtual display (Xvfb) inside Selenium Grid
nodes, and is streamed back to each user over noVNC embedded in the page.
Headless Chrome would start cleanly but leave nothing for anyone to click,
which defeats the entire feature.

  One Grid node = one concurrent recording session.

The original error you reported --
  "session not created: Chrome instance exited"
-- was caused by the application passing desktop-oriented Chrome flags that
cannot work in a container. That is fixed in code. The remaining work is
standing up the browser infrastructure.

A2. [DECISION NEEDED] How many concurrent recording sessions?
--------------------------------------------------------------------------
App Service CANNOT scale browsers dynamically - sidecar containers are
declared statically, so the node count is fixed and becomes a hard ceiling on
simultaneous recordings.

For a POC this is a reasonable trade-off: pick a number, and we will show
users a clear "all browsers busy" message when it is reached.

If recording must scale with the team, the move is Azure Container Apps -
KEDA ships a "selenium-grid" scaler that scales nodes off the Grid's pending
session queue. AKS works too.

WE NEED THE NUMBER EITHER WAY.
Capacity rule of thumb: ~1 GB RAM per concurrent Chrome, plus the app.

PHASE 2 - BUILD THE IMAGE   (deploy/Dockerfile)
--------------------------------------------------------------------------
[ ] KEEP THE python:3.12-slim BASE IMAGE.
    This is not a preference. The code uses a backslash inside an f-string
    expression (legal only from Python 3.12, PEP 701). On 3.11 or older the
    app dies with a SyntaxError at import.

[ ] DO NOT RE-ADD THE WINDOWS PACKAGES.
    pywin32, pywinauto and comtypes now carry PEP 508 markers
    (sys_platform == "win32") so pip skips them on Linux. Without those
    markers the build HARD-FAILS - they have no Linux wheel and no Linux
    source build.

[ ] Verify .env is absent from the built image. .dockerignore excludes it,
    but please confirm - see the gotchas section for why this matters more
    than it appears.


--------------------------------------------------------------------------
PHASE 3 - STAND UP SELENIUM GRID
--------------------------------------------------------------------------
[ ] Deploy a Hub plus Chrome nodes based on selenium/node-chrome
    (Xvfb + fluxbox + headed Chrome + VNC).

[ ] Set --shm-size=2g on EVERY node.
    /dev/shm defaults to 64 MB in Docker and Chrome crashes on heavy pages
    without this. It surfaces as the same "Chrome instance exited" error.

[ ] Set SE_NODE_MAX_SESSIONS=1.
    Two sessions on one node share a single X display - users would see and
    be able to click each other's browser.

[ ] Set SE_SESSION_TIMEOUT=300.
    People close tabs without stopping a recording. Without server-side
    reaping, those dead sessions pin nodes forever until nobody can record.

[ ] Enable VNC: SE_START_VNC=true, screen 1920x1080.

[ ] CHANGE SE_VNC_PASSWORD from the placeholder in docker-compose.yml.

================================================================================
PART D - GOTCHAS THAT COST DAYS
================================================================================
Each of these fails quietly or misleadingly.

  python:3.12+ base image
      -> SyntaxError at import on 3.11 (backslash in f-string, PEP 701)

  PYTHONPATH=/app
      -> every "from config..." / "from utilities..." import fails; app never
         starts

  PROTOCOL_BUFFERS_PYTHON_IMPLEMENTATION=python
      -> the native protobuf extension segfaults and SILENTLY kills the
         Streamlit server

  Grid Hub on 127.0.0.1, not a container name
      -> App Service sidecars share a network namespace; "chrome:4444" gives
         "host not found in upstream" and nginx refuses to start

  --shm-size=2g on Chrome nodes
      -> Chrome crashes on heavy pages; surfaces as the same
         "session not created: Chrome instance exited" error

  Upgrade / Connection headers in nginx
      -> Streamlit hangs on "Please wait", noVNC shows a grey frame.
         NO ERROR IS LOGGED in either case.

  SE_SESSION_TIMEOUT
      -> abandoned sessions pin nodes permanently until nobody can record

  SE_NODE_MAX_SESSIONS=1
      -> users share one X display and can see and click each other's browser

  .env excluded from the image
      -> several call sites use load_dotenv(override=True), where the FILE
         beats real environment variables. A stray .env in the image would
         silently override your App Service settings while the portal still
         displayed the correct values. Extremely hard to diagnose.
