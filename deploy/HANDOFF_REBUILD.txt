WHAT CHANGED SINCE YOUR BUILD
-----------------------------
1. noVNC would not connect  (d2c3c2ec)  <-- your reported issue
   noVNC resolves its WebSocket path against the ORIGIN, not the page, so the
   default became wss://<app>/websockify. That does not match nginx's /vnc/
   location, so it fell through to Streamlit, which rejects the handshake -
   and noVNC just sits on "connecting" with nothing logged anywhere.
   Fixed by pointing the client at /vnc/websockify, plus a root /websockify
   location as a fallback, plus 3600s read timeouts so an idle recording
   session is not cut off mid-way.

2. Live browser panel on ALL browser flows  (e860041d)
   Previously only the IQEA recorder had one. Self-healing computed the URL and
   never rendered a panel; the PBI validator had none at all, while telling the
   user to "log into Power BI in the browser window". Power BI needs an
   interactive login, so that flow was impossible in Azure. All three now share
   one panel implementation.

3. MCP DOM collector now works in Azure  (e860041d)
   The image had no node at all, so the self-healing DOM collection step could
   not run. Node, @playwright/mcp and Chromium are now baked in, and the MCP
   config uses the pre-installed binary with --headless --no-sandbox instead of
   `npx -y @playwright/mcp@latest` (which re-downloads from npmjs on every run
   and fails under restricted egress).

4. API performance reporting + its dependencies  (bb599035)
   requirements.txt gained fpdf2, azure-identity, azure-mgmt-monitor,
   azure-core. Without them api_validator.py dies at import.


!! READ THIS BEFORE BUILDING - PLAN SIZE !!
-------------------------------------------
Item 3 means TWO browsers can be live at once: Playwright Chromium inside the
app container (DOM collection) plus Chrome in the sidecar (the user's session).
Peak is roughly 2.5 GB.

  A 2 GB plan WILL be OOM-killed during self-healing.
  Minimum P0v3 (4 GB). P1v3 (8 GB) preferred.

Check and resize first:
    az appservice plan list -o table
    az appservice plan update --name <PLAN> --resource-group Quality-Engineering-CoE --sku P1V3

The image is also ~400-500 MB larger because of Chromium, so the build and the
first pull take longer. That is expected, not a fault.

STEP 4 - TWO THINGS TO CONFIRM
------------------------------
4a. WebSockets enabled on the App Service (noVNC and Streamlit both need it):

    az webapp config show --name iqea-poc \
      --resource-group Quality-Engineering-CoE --query webSocketsEnabled

    If false:
    az webapp config set --name iqea-poc \
      --resource-group Quality-Engineering-CoE --web-sockets-enabled true

    Streamlit uses WebSockets too, so it is probably already on - but it is one
    command to rule out.

4b. The Chrome sidecar must have SE_START_VNC=true, or port 7900 is not
    listening and the panel stays blank no matter what nginx does:

      SE_START_XVFB        = true
      SE_START_VNC         = true      <-- REQUIRED
      SE_VNC_NO_PASSWORD   = true
      SE_SCREEN_WIDTH      = 1920
      SE_SCREEN_HEIGHT     = 1080
      SE_NODE_MAX_SESSIONS = 1
      SE_SESSION_TIMEOUT   = 3600     <-- RAISED from 300

    SE_SESSION_TIMEOUT was 300 (5 min). Grid counts a session idle when no
    WebDriver command arrives - and a user reading a page inside the live view
    issues none, because their clicks go to Chrome, not to IQEA. So sessions
    died under people mid-task, and the live view then showed a stale screen or
    the Grid start page.
    The app now also pings the session once a minute by itself, so this value is
    belt-and-braces rather than the only defence.

    SE_VNC_PASSWORD must MATCH the app's [BROWSER] novnc_password (default
    "secret"), or the live view prompts for a password. Alternatively set
    SE_VNC_NO_PASSWORD=true here and leave novnc_password blank.

    Portal: App Service > Deployment Center > Containers > chrome > edit.

      ready=True nodes=1 slots=1

Reading a failure:
  - GRID REACHABLE: NO            -> the printed message names the exact
                                     address to change
  - LIVE VIEW: MISROUTED          -> /vnc/ is returning the Streamlit app;
                                     check NOVNC_UPSTREAM and WEBSITES_PORT
  - probe errors but LIVE VIEW ok -> normal. These probes use the container's
                                     loopback; the browser arrives via App
                                     Service ingress, so a probe error does not
                                     mean the panel is broken. Confirm in the UI.
